I'm done, now what about Redis?

What is Redis? Redis is a database stored in RAM temporarily. Redis offers a versatile type for flexibility, implementation, and deployment. In terms of flexibility, Redis has the ability to store data in memory in any structure, for example, it can store strings, hashes, or lists, etc, and we only need to communicate with Redis to retrieve the cache. Caches are very powerful because they are temporary, so they can be used for validation or rechecking. In terms of implementation, Redis can be documented for any programming language, for example, C, Java, JS, Python, and all SDKs if you want to adopt it from your programming language. It is compatible with IoT architectures, Mobile Development, Web Development, API, Microservice. In terms of deployment, Redis uses the concept of primary nodes and secondary nodes. So, if used for publishing, the primary node will immediately publish and automatically communicate with Redis to retrieve the cache and place it on the secondary node. Redis has the advantage of being single-threaded, which handles each thread individually, thus providing fast performance. However, it does not handle multiple threads. Instead, Redis will continue to handle a single thread even in multi-threaded situations.

What is Key-Value? Key-value is adopted from NoSQL and JSON. The concept of a key is simply a field, and its value is derived from that key. Therefore, keys and values ​​always go hand in hand. To search for a value, you must know the key being searched for. To update a value, you must know the key being searched for. To delete a value or key, you must know both the key and the value. And to insert data, you must initialize the key and the value.

What is TTL? TTL stands for Time To Live, which is the time limit for data upload connections over a network. For example, if a sender uploads data over a network so that a recipient can receive data from the sender, if the recipient uses a router to connect to the recipient, the TTL can decrement its lifetime by -1 for each hardware connection to the recipient, such as using only a router, bridge, or other hardware. If the TTL reaches 0, the recipient cannot receive data from the sender, because the TTL must continually decrement its lifetime if it continues to forward communication using hardware to the recipient.
The TTL (Time To Live) in Redis is the length of time a data (key) can be stored in Redis before it is automatically deleted.
Redis itself is an in-memory database, so all data resides in RAM. Because RAM is limited, Redis provides a TTL (Time-To-Release Time) so that data that is only needed temporarily can be deleted without having to be manually deleted.

What is Storage? Storage is used to store and recover data. For example, if we need to store data, we need to know the storage location and whether we want to recover that data. Therefore, we need to know the storage location. Storage has two types: local and deployment. Local storage only retrieves data from your local environment and does not use the network, while deployment storage allows any user to access the database over the network. Remember, if it is deployment, access rights must be initialized first.
