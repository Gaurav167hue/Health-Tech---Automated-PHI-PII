Today I'm going to create the source code for Token Mapping.

I'm only using my dummy text data from the back-end to mock NLP in dumy_text_nlp.py because it doesn't have entities, so I coded for token mapping in various ways. First, I detected using split(), so I only got one detection for name because split only uses indexes. So my dummy data has text for the original text and type for the redacted text. My dummy data needs to detect two replacements, so my test only gets one detection for name detection. However, if my text is only 'Jhon Smith' and the type is 'PERSON' but have different indexes, then for PERSON it only gets Jhon. So I coded again for token mapping using Sequence Matcher or Algorithm Alignment. The concept of Algorithm Alignment is to find the text and type if they are different, and if they are different, replace them. However, this code has a weakness because from my dummy data, the type only replaces my counter, so if the data is repeated for redacting, it doesn't know the next counter. So I coded again for token mapping using Anchor. So, the Anchor concept simply looks for the left and right anchors, allowing for the distance between the left and right anchors, so it can be an entity for multiple words. Again, using split(), I rebuilt the code for token mapping using anchor + cursor. The Anchor concept is simply a pointer, and the Cursor is a tool. The cursor only detects if it has detected an entity, so it doesn't return to the next text. So, I built the final token mapping using Progressive Anchor Matching, so the Cursor + Anchor concept: The Cursor is simply a pointer, and the Anchor is simply a tool. The Cursor provides constraints for the Anchor, allowing the Anchor to easily detect entities.
