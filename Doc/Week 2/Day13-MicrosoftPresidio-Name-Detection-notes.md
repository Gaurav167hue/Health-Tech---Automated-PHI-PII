Today, I will write code to integrate Microsoft Presidio for NLP purposes.

Conceptually, Microsoft Presidio is an open-source framework from Microsoft designed to detect and analyze Personally Identifiable Information (PII), as well as to perform redaction or anonymization. PII encompasses personal information—such as hospital medical data—that requires protection because it contains patient details, visit records, physician data, and so forth.

The first step is to download the Microsoft Presidio libraries by running the commands `pip install presidio-analyzer` and `pip install presidio-anonymizer`.
For the second step, I am implementing Presidio solely on the back-end. At this stage, I only require the analysis logs and have not yet integrated it into the main pipeline, as my current focus is understanding how to obtain these analysis results for the subsequent implementation phase.

I updated the `nlp_service.py` code to utilize Microsoft Presidio; I am using a spaCy model, and the model detects entities only when the input text is in English (_en_).

Now, I will write code to detect the entities "Patient" and "Doctor."
The approach involves using the back-end to test responses from Microsoft Presidio. If Presidio detects a `[PERSON]` entity, my code examines the surrounding text; for instance, if the word "Patient" or "Doctor" is found, the system captures the 30 characters preceding that name. This allows text such as "Patient Jhon Smith" to be transformed into `[PATIENT]` and "Doctor Reyhan Rafaidhil" into `[DOCTOR]`. Although Presidio initially detects only `[PERSON]`, my code converts this to `[PATIENT]` or `[DOCTOR]` based on the context. It should be noted that the name must consist of at least two words; if the input is simply "Patient HAN," the model might not be able to determine whether "HAN" is a `[PERSON]`, `[ORG]`, or another category. Therefore, a person's name must consist of at least two words for the model to detect it as `[PERSON]` more accurately. You can view evidence of this in the images under the "Week 3" category, specifically in the file named 'Patient & Doctor Detected.png'.

Next, I wrote the code for the Address Detection feature.
The implementation runs entirely on the back-end because I use Microsoft Presidio for analysis; this allows analysis results originally labeled as [LOC], [LOCATION], or [GPE] to be re-categorized as [ADDRESS]. This mechanism relies on code that examines the surrounding text—for instance, if terms like "JL" or "Jakarta" are detected, the system captures the preceding 40 characters and designates that segment as [ADDRESS].

Finally, I wrote the code for context detection using Presidio.
I implemented this context detection because disease names need to be ignored, given that information regarding diseases does not fall under the category of sensitive personal data. I designed detection rules to ignore specific disease-related terms, such as "disease," "syndrome," "disorder," "infection," "cancer," "diabetes," "hypertension," "Parkinson's," and "Alzheimer's." If any of these terms are found, the system skips them (excluding them from both the entity transformation process and the analysis). You can see evidence of this implementation in the "Week 3" images, specifically in the file named "context Detection.png".

It should be noted that for detection, I rely solely on Regex and Microsoft Presidio (which produces output as a _RecognizerResult_ or list object); consequently, I convert the _RecognizerResult_ into a dictionary to ensure compatibility with the final pipeline in `detection_service.py`, which requires the dictionary format. Within `detection_service.py`, I call functions from `person_detector.py`: the `detect_person()` function is used to retrieve the PERSON entity, after which I call `classify_patient()` to convert PERSON to PATIENT and `classify_doctor()` to convert PERSON to DOCTOR.
